# Android requirements for Recent-Recall

Checked 2026-11-02 (third pass). VERIFIED means two sources were opened and read, or the evidence noted. UNVERIFIED means that bar was not met; the note says what was found and what is missing. A search extract alone never counts as a source.

| Topic | Finding | Status | Source |
|---|---|---|---|
| Accessibility service declaration | Service must declare `android.permission.BIND_ACCESSIBILITY_SERVICE`, the `android.accessibilityservice.AccessibilityService` intent filter and an `android.accessibilityservice` meta-data XML. Without the intent or the permission the system ignores the service. | VERIFIED | https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.html (Declaration section, read 2026-11-02) ; https://developer.android.com/guide/topics/ui/accessibility/service |
| Global actions | `performGlobalAction()` is the call for system-wide actions such as Back and notifications. | VERIFIED | same guide |
| GLOBAL_ACTION_RECENTS (behaviour) | Constant exists, value 3. Current reference: "Action to toggle showing the overview of recent apps." Original AOSP text: "Action to open the recent apps." It toggles. | VERIFIED | https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.html (read 2026-11-02) ; AOSP https://android.googlesource.com/platform/frameworks/base/+/56a2301/core/java/android/accessibilityservice/AccessibilityService.java |
| GLOBAL_ACTION_RECENTS (API level) | The earlier text said "since API 21". Probably wrong, since the constant sits in very old AOSP source. The per-constant "Added in API level" line was cut off when the page was fetched, so no number is confirmed. Do not rely on 21. | UNVERIFIED (API level only) | pages above |
| GLOBAL_ACTION_QUICK_SETTINGS (behaviour) | Constant exists, value 5, "Action to open the quick settings." | VERIFIED | same reference and AOSP source |
| GLOBAL_ACTION_QUICK_SETTINGS (API level and guard) | Search extracts of two pages (the developer.android.com reference and the archived reference at stuff.mit.edu) read "Added in API level 17 ... Constant Value: 5". The page bodies were truncated when fetched, so this rests on extracts only. If it holds, the app's SDK_INT >= 31 guard is stricter than the platform needs; it is an app decision, not a platform requirement. | UNVERIFIED (extracts, not full reads) | https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.html ; https://stuff.mit.edu/afs/sipb/project/android/docs////reference/android/accessibilityservice/AccessibilityService.html |
| Window content | `android:canRetrieveWindowContent` is only needed to inspect the UI tree. Set false here. Window content is described as a capability the service declares. | VERIFIED | AccessibilityService reference (Retrieving window content) ; accessibility guide |
| Event cost | `typeAllMask` is resource heavy. This app asks only for `typeWindowStateChanged`. | VERIFIED | accessibility guide |
| Overlay type | Decision: use TYPE_ACCESSIBILITY_OVERLAY. The current WindowManager.LayoutParams reference describes it as "Windows that are overlaid only by a connected AccessibilityService", and deprecates the old system alert types for non-system apps in favour of TYPE_APPLICATION_OVERLAY. The AccessibilityService reference has a "Drawing Accessibility Overlays" section. Neither page states in words that SYSTEM_ALERT_WINDOW is not needed, and Manifest.permission was not read. Needs a device check or an explicit statement. | UNVERIFIED (no explicit no-permission statement) | https://developer.android.com/reference/android/view/WindowManager.LayoutParams?hl=en ; AccessibilityService reference (both read 2026-11-02) |
| Foreground service | Apps targeting Android 12+ cannot start a foreground service from the background except in listed cases. This app uses no foreground service. | VERIFIED | https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start |
| Usage access | UsageStatsManager was added in API level 21. Most methods need `android.permission.PACKAGE_USAGE_STATS`; declaring it only signals intent and the user must still grant access in Settings (`Settings.ACTION_USAGE_ACCESS_SETTINGS`). Calling-package-only methods (`queryEventsForSelf`, `getAppStandbyBucket`) need no permission. The app does not use it. Only one opened source. | UNVERIFIED (one opened source) | https://developer.android.com/reference/android/app/usage/UsageStatsManager?hl=en (read 2026-11-02) |
| Package visibility | Targeting API 30+ filters other apps. `<queries>` declares what you need. QUERY_ALL_PACKAGES is for rare cases and Google Play has a policy for it. | VERIFIED | https://developer.android.com/training/package-visibility/declaring |
| Decision on QUERY_ALL_PACKAGES | Declared, because the rules picker must list apps without a launcher icon and system apps. Sideloaded debug build, not on Play. Justification must be restated if ever published. | decision | this document |
| Reboot behaviour | Confirmed only: the system manages the service lifecycle, it starts when the user turns it on and stops when the user turns it off or it calls disableSelf(). No opened page states what happens at reboot. Forum threads seen in search describe both outcomes by device and were not opened. The app never promises persistence and shows live status. | UNVERIFIED | https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.html (Lifecycle) ; settle on the Galaxy A17 by rebooting with the service enabled |
| Restricted settings (sideloaded) | Android 13+ restricts some settings, accessibility included, until the user chooses Allow restricted settings (Settings, Apps, the app, More). Google Help confirms the setting, Android 13+ and accessibility as the example. Android Police (2022) states Android 13 stops sideloaded apps getting accessibility access without that workaround, and that apps installed through the session-based package installer API (app stores) are exempt. Official source does not say "sideloaded"; that wording is from the press source. | VERIFIED (one official plus one press source) | https://support.google.com/android/answer/12623953 ; https://www.androidpolice.com/malware-bypassing-android-13s-security-measures/ (both read 2026-11-02) |
